# Course Reflection

The most difficult concept for me in this course was grasping Java and the overarching ideas behind building complete, full-stack systems. At first, the syntax, the object-oriented principles, and the sheer scale of the concepts felt overwhelming. To overcome this, I took a step back and turned to YouTube. Watching numerous tutorial videos that broke down the core principles into visual, bite-sized explanations was incredibly helpful. Seeing the code being written and explained step-by-step allowed me to finally wrap my head around the whole idea.

Based on the feedback I received, the primary area of my capstone I need to improve is the completeness and scale of my system design documentation. My initial drafts were cut short and drastically underestimated the required enterprise scale of the project. 

Next, I will implement several critical updates. For the backend documentation, I will expand `api-design.md` to include the missing request/response JSON payloads and the 400-500 level HTTP error codes. I will also finish `data-model.md` by adding my example SQL queries, indexing strategies, and a solid justification for choosing SQL over NoSQL. For `architecture.md`, I need to recalculate my estimates for 1 million users, update my Mermaid diagram to include DNS, caches, and background queues, and write out the request lifecycles and single-point-of-failure analyses. Finally, on the frontend, I will quickly remove the `required` attribute from the body textarea in `index.html` and update the `api.js` notification to dynamically display the status code and generated ID (e.g., "Note created (status 201, id 101)").
